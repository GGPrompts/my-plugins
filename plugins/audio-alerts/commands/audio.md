# Audio Alerts Configuration

You are helping the user configure their Claude Code audio alerts. Be conversational — they'll tell you what they want and you make it happen.

## Step 1: Check dependencies and current state

Run ALL of these checks first before showing anything to the user:

1. Check dependencies are installed: run `which edge-tts mpv jq python3` via Bash
2. Read `~/.claude/audio-config.sh` (may not exist yet — that's fine, means defaults)
3. Read `~/.claude/settings.json` to check the `env` section for `CLAUDE_AUDIO`, `CLAUDE_VOICE`, `CLAUDE_RATE`, etc.
4. Detect platform: run `uname -s` (Darwin = macOS, Linux = Linux)

### If dependencies are missing

Guide the user through installation before anything else. Be specific to their platform:

**macOS:**
```bash
brew install mpv jq
pipx install edge-tts    # or: pip install edge-tts
```

**Linux / WSL2:**
```bash
sudo apt install mpv jq   # or yum/pacman equivalent
pipx install edge-tts      # or: pip install edge-tts
```

If `pipx` isn't installed either:
```bash
# macOS
brew install pipx && pipx ensurepath

# Linux
sudo apt install pipx && pipx ensurepath
```

If `python3` is missing, tell them to install Python 3 first — edge-tts requires it.

After installation, re-check with `which edge-tts mpv jq` to confirm. Don't proceed to configuration until all deps are present.

### If CLAUDE_AUDIO is not enabled

If `~/.claude/settings.json` doesn't have `"CLAUDE_AUDIO": "1"` in the env section, tell the user audio alerts are installed but disabled, and offer to enable it. If they say yes, read the current settings.json, add `"CLAUDE_AUDIO": "1"` to the env object (creating it if needed), and write it back. Preserve all other settings.

## Step 2: Show current settings

Present the current config in a clean summary:

```
Audio alerts: ON
Voice: random per-session (from 11-voice pool)
Speech rate: +20%
Playback speed: 1.0x
Volume: +0%
Pitch: +0Hz
Announce tools: yes
Announce session start: yes
Announce ready: yes
Tool debounce: 1000ms
Custom clips: none
```

For each setting, show the effective value — check env vars from settings.json first (they override), then audio-config.sh, then the hardcoded default.

Then tell them: "What would you like to change? You can say things like 'make it faster', 'use a British female voice', 'turn off tool announcements', 'make it quieter', etc."

## Step 3: Handle their request

### Voice changes
- Run `edge-tts --list-voices` via Bash and filter to find matching voices
- If they say "British" → filter `en-GB-*`, "Australian" → `en-AU-*`, etc.
- If they say "female" or "male" → filter by gender column
- If they say "random" → remove `DEFAULT_VOICE` / `CLAUDE_VOICE` (default behavior)
- **Preview**: After selecting a voice, generate a short sample: `edge-tts -v "VOICE_NAME" --rate "+20%" -t "Hello, I'm your new Claude assistant voice" --write-media /tmp/audio-preview.mp3 && mpv --no-video --really-quiet /tmp/audio-preview.mp3`
- Ask "Do you like this voice?" before saving

### Speed/rate changes
- "faster" → increase `DEFAULT_RATE` (e.g. `+20%` → `+35%`) or increase `PLAYBACK_SPEED`
- "slower" → decrease rate or speed
- Explain the difference if asked: rate changes the TTS generation (more natural), speed changes mpv playback (mechanical but instant)

### Volume changes
- "quieter" / "louder" → adjust `DEFAULT_VOLUME` (e.g. `+20%`, `-30%`)

### Toggle changes
- "turn off tool announcements" → `ANNOUNCE_TOOLS=false`
- "only tell me when you're ready" → `ANNOUNCE_TOOLS=false`, `ANNOUNCE_SESSION_START=false`, `ANNOUNCE_READY=true`

### Debounce
- "too many announcements" → increase `TOOL_DEBOUNCE_MS` (default 1000, try 2000-3000)
- "announce every tool" → set `TOOL_DEBOUNCE_MS=0`

## Step 4: Write the config

Write changes to `~/.claude/audio-config.sh`. This file is sourced by the audio-announcer script. Format:

```bash
# Audio Alerts Configuration
# Generated by /audio command

# Voice (comment out for random per-session)
DEFAULT_VOICE="en-GB-SoniaNeural"

# Speech settings (baked into TTS audio files)
DEFAULT_RATE="+20%"
DEFAULT_PITCH="+0Hz"
DEFAULT_VOLUME="+0%"

# Playback speed (mpv multiplier, applied at play time)
PLAYBACK_SPEED="1.0"

# Feature toggles
ANNOUNCE_TOOLS="true"
ANNOUNCE_SESSION_START="true"
ANNOUNCE_READY="true"

# Debounce (ms between tool announcements, 0 to disable)
TOOL_DEBOUNCE_MS="1000"

# Custom clips directory (optional, .mp3 files named: ready, session-start, error, etc.)
# CUSTOM_CLIPS_DIR="$HOME/.claude/audio-clips"
```

If voice is "random", comment out the DEFAULT_VOICE line rather than deleting it.

**Important**: If voice or rate or pitch changed, mention that cached audio files will regenerate on next use (the cache key includes these). If only speed changed, it takes effect immediately.

## Step 5: Clear stale cache if TTS settings changed

If voice, rate, pitch, or volume changed, clear the cached audio so new settings take effect:

```bash
rm -f /tmp/claude-audio-cache/*.mp3
```

## Step 6: Offer to test

After saving, offer: "Want me to test it? I'll play a sample with your new settings."

If yes, run:
```bash
edge-tts -v "VOICE" --rate "RATE" --pitch "PITCH" --volume "VOLUME" -t "Audio alerts configured. Ready to assist." --write-media /tmp/audio-test.mp3 && mpv --no-video --really-quiet --speed=SPEED /tmp/audio-test.mp3
```

## Notes

- The `audio-config.sh` variables are loaded first, then env vars from `settings.json` override them. So `settings.json` always wins. Prefer writing to `audio-config.sh` for audio-specific settings and avoid cluttering settings.json with audio vars beyond `CLAUDE_AUDIO`.
- Voice names are case-sensitive and must match exactly (e.g. `en-US-AriaNeural`, not `aria`)
- Rate format: `+20%`, `-10%`, `+0%` (always include sign and percent)
- Pitch format: `+10Hz`, `-5Hz`, `+0Hz`
- Volume format: `+20%`, `-30%`, `+0%`
- Speed: decimal multiplier like `1.0`, `1.5`, `0.8`
- **Windows native is not supported** (bash scripts). WSL2 works fine.

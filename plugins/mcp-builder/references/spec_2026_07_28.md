# MCP Spec Revision 2026-07-28: What Changed for Server Authors

Dated addendum to the other references in this skill, which predate this revision and
describe the 2025-era protocol. Where they conflict, this file wins. Full spec:
https://modelcontextprotocol.io/specification/2026-07-28 (changelog:
/specification/2026-07-28/changelog). The revision has a formal feature lifecycle now:
deprecated features keep working for a minimum 12-month window, so existing servers are
not broken, but NEW servers should be built to this revision.

## The big shift: MCP is now stateless

- **No more `initialize` / `notifications/initialized` handshake, no `Mcp-Session-Id`.**
  Every request carries its own context in `_meta`:
  `io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientCapabilities`,
  and (SHOULD) `io.modelcontextprotocol/clientInfo`. Servers SHOULD return
  `io.modelcontextprotocol/serverInfo` in each result's `_meta`. Version mismatch returns
  `UnsupportedProtocolVersionError` (-32022).
- **Server state = explicit handles.** List endpoints must not vary per-connection. If a
  server needs cross-call state, mint a handle and take it back as an ordinary tool
  argument. Do not design around sessions.
- **`server/discover` is REQUIRED.** Servers MUST implement it, advertising supported
  protocol versions, capabilities, and identity. Clients may call it before anything
  else, or use it as a backward-compat probe.
- **Streamable HTTP hardening:** POSTs now require `Mcp-Method` and `Mcp-Name` headers.
  SSE resumability is GONE (no `Last-Event-ID`, no event IDs): a broken response stream
  means the client re-issues the request with a new ID, so make tools idempotent or
  handle-based where retries matter.
- **Server-to-client notifications** go through a single opt-in `subscriptions/listen`
  stream (replaces the GET endpoint and `resources/subscribe`/`unsubscribe`).
  Request-scoped notifications (`notifications/progress`, `notifications/message`) still
  flow on the originating request's response stream.

## Results: `resultType` and MRTR

- Every result now carries a required `resultType`: `"complete"` or `"input_required"`.
- **Multi Round-Trip Requests (MRTR)** replace ALL server-initiated requests
  (`elicitation/create`, `sampling/createMessage`, `roots/list`). To ask the client for
  something mid-request, return `resultType: "input_required"` with `inputRequests`; the
  client retries the ORIGINAL request adding `inputResponses`. Correlate across retries
  with your own identifier in `requestState`.

## Caching (new requirements)

- `tools/list`, `prompts/list`, `resources/list`, `resources/read`, and
  `resources/templates/list` results MUST include `ttlMs` (freshness hint) and
  `cacheScope` (`"public"` | `"private"`).
- Return tools in a **deterministic order** (SHOULD): clients cache tool lists into LLM
  prompts, and stable ordering preserves prompt-cache hits.

## Deprecated: do not build these into new servers

| Deprecated | Build instead |
|---|---|
| Sampling (`sampling/createMessage`) | Integrate directly with an LLM provider API server-side |
| Roots | Take directories/files as tool parameters, resource URIs, or server config |
| Logging (`logging/setLevel`, `notifications/message`) | Log to stderr (stdio) or OpenTelemetry; per-request level via `_meta` `io.modelcontextprotocol/logLevel` |
| HTTP+SSE transport (the old two-endpoint kind) | Streamable HTTP |
| OAuth Dynamic Client Registration (RFC 7591) | Client ID Metadata Documents |

Also removed outright: `ping`, `notifications/roots/list_changed`, resource
subscribe/unsubscribe (see `subscriptions/listen`). Resource-not-found now returns
-32602, not -32002. Error codes -32020 to -32099 are reserved for the spec; keep
implementation-defined codes in -32000 to -32019.

## Extensions (formalized) and MCP Apps

Capabilities now carry an `extensions` field on both sides; extensions are opt-in and
identified as `{vendor-prefix}/{name}` (official ones use `io.modelcontextprotocol/`).
Notable official extensions:

- **MCP Apps (`io.modelcontextprotocol/ui`)** — tools declare interactive UI: the tool
  description points at a `ui://` resource via `_meta.ui.resourceUri`; the host fetches
  it and renders it in a sandboxed iframe; the app talks back over a postMessage
  JSON-RPC dialect (`ui/*` methods plus `tools/call` proxied through the host).
  Supported by Claude / Claude Desktop, VS Code Copilot, M365 Copilot, and others.
  If a server offers UI-enhanced tools, it MUST still return meaningful text content
  for clients without the extension (graceful degradation). Ship self-contained HTML
  bundles; declare any external origins in `_meta.ui.csp` (strict hosts may deny them).
  Docs: https://modelcontextprotocol.io/extensions/apps/overview
- **MCP Tasks (`io.modelcontextprotocol/tasks`)** — long-running operations moved out of
  core: polling via `tasks/get`, mid-flight input via `tasks/update`, durable handles.

## Authoring checklist delta (add to the language-guide checklists)

- [ ] `server/discover` implemented with accurate versions/capabilities
- [ ] No reliance on initialize handshake or sessions; state via explicit handles
- [ ] `resultType` on every result; MRTR for mid-request input needs
- [ ] `ttlMs` + `cacheScope` on all list/read results; deterministic tool ordering
- [ ] Tools idempotent or retry-safe (no SSE resumability)
- [ ] No sampling/roots/logging in new code
- [ ] If shipping UI: MCP Apps extension, with text fallback for non-supporting hosts
- [ ] SDK pinned to a release that supports 2026-07-28 (check the SDK changelog; the
      revision shipped 2026-07-28 and SDK support may lag it)
